## Content model (why each site reads differently)

Shared, identical across sites by design: product specs and prices (spec tables, product cards, compare tables, price list), the financing legal disclaimer, form field labels, navigation and footer, and the voucher mechanics.

Store-specific, all in `src/data/copy/<store>.json` (~12,500 words per store after two rounds, Sep 21 and Sep 28, 2026):
- Round 1: `angle`, `categories.hot-tub|swim-spa|sauna` (intro, 3 body paragraphs, 5 FAQs), `productNotes` (fallback by size), `financing`, `showroom`, `towns.<Town>` (lead, 2 body paragraphs, drive) for every service-area town.
- Round 2: `productBlurbs.<slug>` (a 50 to 90 word store-written paragraph for every one of the 72 products, shown as "Owning the <model> in <City>"), and `ui` with every piece of page boilerplate: salebarText, heroTail, trustBadges, hotTubsIntro, finderIntro, swimHomeIntro, saunaHomeIntro, visitSteps, brandBlurbs, specialsIntro, specialsHeroLead, redTagWhy (heading, lead, 3 reasons, summary), alsoOnIntro, specialSummaries (per special id, overrides the specials.json summary for that store, including in schema), claimSteps, claimModalNote, leadReassure, productTrust, productFloorLine ({model} placeholder), productExtras, redTagCallout, compareIntro, productFormSub, financingLead, financingSteps, financingFaq, finderPageLead, finderEmailNote, priceListLead, thankYouLead, gazeboIntro, massageIntro, coldPlungeIntro, and (Sep 28) `commercial` (eyebrow, heading, lead) and `buyCanadian` (heading, lead, points[3], pageLead, body[3], faq[2]).
Templates read these through `copy`, `ui` and `productBlurb()` in `src/lib/site.ts` and fall back to the shared text when a key is missing, so a new store works before its copy file is written. Model names in any copy string are auto-linked to product pages by `linkModels()`.

Measured Sep 28 across all page types: prose overlap between any two sites (8-word sequences, excluding navigation, spec tables, product cards, forms and modals) is 21 to 26%, down from 70% before round 1. Whole-page overlap including the spec and navigation layers is 43 to 47%. Rules for all copy: no em or en dashes, no exclamation marks, Canadian spelling, no invented statistics, bylaws or superlatives, prices only from the catalogue, never say a Chill Tub is included with a sauna (that promotion ended Sep 28). Buy Canadian copy only claims what is verifiable: the Wellness Shop is an Ontario company, 25 years, started as one local hot tub store, eight showrooms, local delivery crews and service; Serenity saunas are built in Canada; Jacuzzi and the Wellness Shop Ontario series are built in the USA, Nordic in Michigan, Aquasolus in Europe. Never call the tubs Canadian-made.

Catalogue correction Sep 28: Clearlight Sanctuary 5 seats 5 (the spreadsheet said 3).

## How Michael asks for updates (one commit, all six sites redeploy)

- Prices / specs: `src/data/products.json` (or update `data-source-catalog.xlsx` and run `npm run products`; the build script strips the stale "Not incl. in No-Tax sale" note).
- Hero headline, banners, financing line, countdown: `src/data/promos.json`.
- In-store specials: `src/data/specials.json` (plus per-store summary wording in each copy file's `ui.specialSummaries`).
- Store phone / tracking number / hours / staff / towns / GTM id / focus: `src/data/locations/<store>.json`.
- Local written copy: `src/data/copy/<store>.json` (add a town there when adding it to serviceAreas; add a `productBlurbs` entry when adding a product).
- New dataLayer events: add to EVENTS in `scripts/build-gtm-import.mjs`, re-import into GTM, publish.

## Deploy path from a Claude session

The cloud sandbox git proxy refuses pushes to this repo. Workaround: `git bundle create /mnt/user-data/outputs/wellness-shop-<sha>.bundle main` (use a NEW filename each time; the device bridge serves a cached copy for a reused filename) -> `device_commit_files` into `Wellness Shop Imagery/_deploy/` (the connected folder is on the Desktop: `/Users/michaellandry/Desktop/Wellness Shop Imagery`) -> on the Mac (`device_bash`) in `$HOME/ws-push`: `git fetch <bundle> main && git merge --ff-only FETCH_HEAD && git push https://mlandry-landry:<PAT>@github.com/mlandry-landry/wellness-shop.git main`. Vercel auto-deploys all six projects. The Vercel MCP cannot see these projects; env vars are set in the Vercel dashboard via Chrome. Do not chain `pkill` with `git commit` in one Bash call (the shell exits before the commit runs). Neither the sandbox nor the Mac shell can reach the .vercel.app sites or i.ytimg.com; verify live pages through Chrome.
